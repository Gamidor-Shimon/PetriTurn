# SBS PetriPlater — Gamidor

מכשיר לסיבוב צלחת פטרי בזמן זריעת חיידקים.
הרובוט מחזיק את הלופה, והמכשיר מסובב את הצלחת לפי תוכנית שנשמרה מראש בבקר.

```
Robot → platter.exe (Python) → USB → XIAO ESP32-C3 → TMC2209 → NEMA17 → Petri dish
                 ↑
   platter_gui (program editor) → writes programs into the controller's flash
```

הפרויקט בנוי משלושה חלקים:

1. **קושחה** לבקר — `firmware/PetriPlatter/PetriPlatter.ino`
2. **שורת פקודה לרובוט** — `host/platter.py` (לאחר בנייה: `platter.exe`)
3. **תוכנת ניהול (GUI)** — `host/platter_gui.py`, בעיצוב Gamidor

## חומרה

הפירוט המלא, רגל אחר רגל, עם שרטוטים ובדיקות: **[WIRING.md](WIRING.md)**.
הקופסה המודפסת (130 × 96, עם פאנל חיבורים), חלקים, הדפסה והרכבה: **[enclosure/README.md](enclosure/README.md)**.
לוח ההלחמה, סידור רכיבים וחיבורים: **[perfboard/README.md](perfboard/README.md)**.

### רכיבים

| רכיב | דגם / ערך |
|---|---|
| בקר | Seeed XIAO ESP32-C3 |
| דרייבר | TMC2209 (לוח V985), חיישת זרם `R110` = 0.11Ω |
| מנוע | LAM M1173040, NEMA17, ‏1.8°, ‏0.7A, ‏9.3Ω לסליל |
| ספק | 24V, לפחות 1.5A |
| קבל | 100µF / 35V אלקטרוליטי |
| נגדים | 1kΩ, ‏10kΩ |

### חיווט בקר ← דרייבר

| XIAO | GPIO | דרייבר TMC2209 | הערה |
|---|---|---|---|
| `3V3` | — | `VDD` (ימין, פין 7) | מתח לוגיקה |
| `GND` | — | `GND` (ימין, פין 8) | אדמה משותפת, חובה |
| `D1` | GPIO3 | `EN` (שמאל, פין 1) | + נגד **10kΩ מ-EN אל 3.3V** — המנוע כבוי בזמן עליית הבקר |
| `D2` | GPIO4 | `STEP` (שמאל, פין 7) | |
| `D3` | GPIO5 | `DIR` (שמאל, פין 8) | |
| `D4` | GPIO6 | `USART` (שמאל, פין 5) | **דרך נגד 1kΩ** |
| `D5` | GPIO7 | `USART` (שמאל, פין 5) | חוט ישיר |
| — | — | `MS1`, `MS2` | אל GND — כתובת דרייבר 0 |
| — | — | `PDN`, `CLK`, `DIAG`, `INDEX`, `VREF` | לא מחוברים |

- פינים `D0`, `D8`, `D9` של ה-XIAO הם פיני אתחול — **לא לחבר אליהם דבר**.
- `D6`/`D7` נשארים פנויים (הבקר מדפיס עליהם הודעות אתחול).
- **חוטים ליד שקע ה-USB-C** עלולים למנוע מהתקע להיכנס עד הסוף, והמחשב לא יזהה את הבקר. להרחיק אותם מהשקע.

### חיווט ספק ומנוע

| מ- | אל | הערה |
|---|---|---|
| ספק 24V (+) | `VM` (ימין, פין 1) | + רגל **+** (הארוכה) של קבל 100µF, צמוד לדרייבר |
| ספק 24V (−) | `GND` (ימין, פין 2) | + רגל **−** (הפס) של הקבל |
| מנוע שחור | `A2` (ימין, פין 3) | |
| מנוע ירוק | `A1` (ימין, פין 4) | |
| מנוע אדום | `B1` (ימין, פין 5) | |
| מנוע כחול | `B2` (ימין, פין 6) | |

בדיקה לפני חיבור המנוע: שחור–ירוק ≈ 9.3Ω, אדום–כחול ≈ 9.3Ω.

**סדר הדלקה:** USB קודם, 24V אחר כך. **כיבוי:** לשחרר את הצלחת, לכבות 24V, ואז USB.
כשאין 24V הדרייבר לא עונה (`DRV=0x00`) — זה תקין.

## התקנה ראשונה

### 1. קושחה (Arduino IDE)

1. **Boards Manager:** להתקין `esp32` by Espressif.
2. **Library Manager:** להתקין `TMCStepper` (teemuatlut) ו-`AccelStepper` (Mike McCauley).
3. לפתוח את `firmware/PetriPlatter/PetriPlatter.ino`.
4. **Tools:**
   - Board: `XIAO_ESP32C3`
   - USB CDC On Boot: **`Enabled`** — בלי זה אין תקשורת דרך ה-USB
   - Port: הפורט של הבקר
5. Upload.

אם הצריבה נכשלת: לנתק USB, להחזיק את כפתור **BOOT**, לחבר USB, לשחרר, ולצרוב שוב.

בדיקה ב-Serial Monitor (115200, סוף שורה `Newline`): לשלוח `STATUS`.
עם 24V מחובר צריך לחזור `DRV=0x21`.

### 2. תוכנה במחשב

צריך Python 3.11 ומעלה. מתיקיית הפרויקט:

```bash
python -m venv .venv
```
```bash
.venv\Scripts\python -m pip install -r requirements.txt
```

הסביבה `.venv` נשמרת בתוך תיקיית הפרויקט. ב-Python שמותקן מ-Microsoft Store,
התקנת PySide6 מחוץ לסביבה כזו נכשלת בגלל נתיבים ארוכים מדי.

### 3. הפעלה

- **GUI:** לחיצה כפולה על `PetriPlatter.bat`
  (לא על `platter_gui.py` ישירות — אז הוא רץ עם ה-Python של המערכת, שאין בו PySide6).
- **שורת פקודה:**

```bash
.venv\Scripts\python host\platter.py status
```

## קובץ ההגדרות platter.ini

נמצא ב-`host/platter.ini` (אחרי בנייה: ליד קובצי ה-exe).
**גם הרובוט וגם ה-GUI קוראים ממנו**, כך שהפורט מוגדר במקום אחד.
אם הקובץ חסר — הוא נוצר מחדש עם ברירות המחדל.

```ini
[connection]
port = COM6          ; USB port of the controller (Device Manager -> Ports)
baudrate = 115200    ; must match Serial.begin() in the firmware

[timeouts]
command = 3          ; seconds to wait for a quick command's reply
run_margin = 10      ; extra seconds on top of a program's estimated time

[gui]
poll_ms = 1000       ; GUI live-status refresh, milliseconds
```

| מפתח | משמעות |
|---|---|
| `port` | פורט ה-USB של הבקר (מנהל ההתקנים ← יציאות COM ו-LPT) |
| `baudrate` | מהירות התקשורת. חייבת להתאים ל-`Serial.begin()` בקושחה |
| `command` | שניות להמתנה לתשובה על פקודה קצרה |
| `run_margin` | שניות נוספות מעבר לזמן המשוער של תוכנית, לפני שנחשב פסק זמן |
| `poll_ms` | קצב רענון המצב החי ב-GUI, במילישניות |

- **חיבור מוצלח ב-GUI לפורט אחר כותב את הפורט החדש לקובץ** — הרובוט ישתמש בו אוטומטית.
- `--port` בשורת הפקודה עוקף את הקובץ לקריאה אחת בלבד.
- שינוי ידני: לערוך, לשמור, ולהפעיל את התוכנה מחדש.
- ערך לא תקין (למשל `baudrate = fast`) — התוכנה מודיעה על כך במפורש.

## תוכנת הניהול (GUI)

### עמודים

| עמוד | מה יש בו |
|---|---|
| **Programs** | 20 תאי תוכניות בבקר, עורך צעדים, שמירה והרצה |
| **Manual control** | החזקה / שחרור של הצלחת, סיבוב ידני, **הדגמה (demo)**, מצב חי, מקרא ערכים |
| **Info** | גרסה, מחבר, ופקודות הרובוט |

בשורה העליונה, תמיד גלויים: פורט, Connect, מצב חיבור, מצב דרייבר (`DRIVER OK` / `NO DRIVER`),
מצב מנוע (`HELD` / `FREE`), פעילות (`IDLE` / `RUNNING`) וכפתור **STOP**.
בתחתית — קונסולה עם כל פקודה ותשובה, שנשמרת גם ל-`host/logs/`.

### הדגמה (demo)

בעמוד **Manual control**, בכרטיס **demo**:

- **Start demo** — לולאה של 14 סיבובים, עם ונגד כיוון השעון, ב-5 עד 120 RPM
  (כ-39 שניות לסבב). כל סבב מסתיים בנקודה שבה התחיל. חוזר על עצמו עד שעוצרים.
- **Stop demo** — עוצר מיד, גם באמצע סיבוב. גם **STOP** בשורה העליונה עוצר את ההדגמה.
- תוך כדי מוצג הסבב, הצעד והסיבוב הנוכחי. שאר כפתורי התנועה נעולים.
- ההדגמה רצה מה-GUI ולא נשמרת בבקר — היא לא תופסת תא תוכנית.

### יצירת תוכנית

1. **Connect** לפורט של הבקר.
2. לבחור תא ברשימה משמאל (1–20).
3. **Name** — שם התוכנית (עד 24 בייטים; בעברית כ-12 אותיות; בלי `| , =`).
4. להוסיף צעדים עם **Add**:

| צעד | פרמטרים | מה קורה |
|---|---|---|
| **Rotate** | Turns, RPM | סיבוב. מספר שלילי = כיוון הפוך. אפשר שבר (0.25 = רבע סיבוב) |
| **Wait** | שניות | המתנה. הצלחת נשארת במצבה (מוחזקת או חופשית) |
| **Hold dish** | — | המנוע מחזיק — הצלחת נעולה |
| **Release dish** | — | המנוע משוחרר — הצלחת מסתובבת ביד |

5. **Save to controller** — נשמר בזיכרון הבקר, נשאר גם אחרי כיבוי.
6. **Run on controller** — הרצת בדיקה.

- **סיבוב תמיד רץ כשהמנוע מחזיק**, גם אחרי צעד Release.
  צעד אחרון **Hold dish** משאיר את הצלחת נעולה; **Release dish** — משחרר.
- Replace / Remove / ▲ ▼ — עריכת הצעד המסומן בטבלה.
- כפתור שלא יכול לעבוד כרגע — מושבת, ומתחתיו כתוב למה (למשל: אין 24V).
- הזמן המשוער של כל צעד ושל כל התוכנית מוצג בטבלה.

### מגבלות

| | מינימום | מקסימום |
|---|---|---|
| מהירות | 0.1 RPM | 120 RPM |
| סיבוב בצעד אחד | — | 100 סיבובים |
| המתנה בצעד אחד | — | 600 שניות |
| צעדים בתוכנית | 1 | 32 |
| תוכניות | — | 20 |
| תאוצה | קבועה: 1 סיבוב/שנייה² | |

**רק תוכנה אחת יכולה להחזיק את הפורט.** לפני שהרובוט עובד — **Disconnect** או לסגור את ה-GUI.
גם ה-Serial Monitor של Arduino תופס את הפורט.

## שורת הפקודה לרובוט

יש שתי דרכים לעבוד עם הרובוט:

**1. תוכנית שמורה** — הוגדרה מראש ב-GUI:

```bash
platter.exe run 3
```

**2. פקודות ישירות, בלי תוכנית** — הרובוט שולט בכל שלב בעצמו. למשל:

```bash
platter.exe hold
```
```bash
platter.exe rotate 2 30 cw
```
```bash
platter.exe rotate 0.5 10 ccw
```
```bash
platter.exe release
```

(נועלים את הצלחת, ממקמים את הלופה, מסובבים 2 סיבובים עם כיוון השעון ב-30 RPM,
חצי סיבוב נגד כיוון השעון ב-10 RPM, ומשחררים.)

| פקודה | מה היא עושה |
|---|---|
| `platter run <slot>` | מריץ תוכנית שמורה. **חוסם עד סוף התוכנית**, ואז יוצא |
| `platter rotate <turns> <rpm> cw` | סיבוב **עם** כיוון השעון. חוסם עד סוף הסיבוב |
| `platter rotate <turns> <rpm> ccw` | סיבוב **נגד** כיוון השעון. חוסם עד סוף הסיבוב |
| `platter hold` | נועל את הצלחת (המנוע מחזיק) |
| `platter release` | משחרר את הצלחת (מסתובבת ביד) |
| `platter stop` | עוצר תנועה (האטה ועצירה) |
| `platter status` | מצב הבקר (ראו [STATUS](#שדות-status)) |
| `platter list` | רשימת התוכניות השמורות |
| `platter ping` | בדיקת חיבור |
| `platter ports` | הפורטים הזמינים במחשב |

- `<turns>` — מספר סיבובים, חיובי. אפשר שבר: `0.25` = רבע סיבוב. עד 100.
- `<rpm>` — מהירות, 0.1 עד 120.
- `cw` / `ccw` — **כשמסתכלים על הצלחת מלמעלה.**
- סיבוב תמיד רץ כשהמנוע מחזיק; אחרי הסיבוב הצלחת **נשארת נעולה** עד `release`.
- `enable` / `disable` — שמות ישנים ל-`hold` / `release`, עדיין עובדים.
- `--port COM7` — פורט לקריאה זו בלבד. בלי זה — מ-`platter.ini`.

### קודי יציאה

| קוד | משמעות | מה הרובוט צריך לעשות |
|---|---|---|
| `0` | הצליח | להמשיך |
| `1` | פסק זמן, אין תשובה, הפורט תפוס, הדרייבר לא עונה, או STOP | לעצור ולהתריע |
| `2` | פקודה שגויה, ערך מחוץ לטווח, או תא ריק | לבדוק את הפקודה / התוכנית |

ההודעה (`OK` / `ERR <סיבה>`) נכתבת ל-stdout / stderr.

### תזמון

- הפעלה של `platter.exe` לוקחת כשנייה לפני שהפקודה נשלחת (נמדד: 0.85 שניות).
- `run` יוצא רק כשהתוכנית נגמרה. זמן ההמתנה המקסימלי = הזמן המשוער + `run_margin`.
- פתיחת הפורט **לא מאתחלת את הבקר** — הצלחת נשארת מוחזקת בין הרצות
  (נבדק: `UP` ממשיך לעלות בין קריאות).
- Ctrl+C בזמן `run` שולח STOP לבקר.

## פרוטוקול התקשורת עם הבקר

USB, ‏115200, כל שורה מסתיימת ב-`\n`. לכל פקודה — שורת תשובה אחת: `OK...` או `ERR <סיבה>`.
שורות שמתחילות ב-`#` הן הודעות מידע (למשל בעליית הבקר).

| פקודה | תשובה | הערה |
|---|---|---|
| `PING` | `OK PONG` | |
| `INFO` | `OK SLOTS=20 MAX_STEPS=32 MIN_RPM=0.1 MAX_RPM=120 MAX_DEG=36000 MAX_WAIT_MS=600000 ACCEL=1` | מגבלות הבקר |
| `STATUS` | `OK EN=.. BUSY=.. STEP=i/n POS=.. DRV=0x.. CUR=.. UP=.. URX=..` | |
| `DIAG` | `OK A0=12/0x21 ... IOIN=.. GSTAT=.. DRV_STATUS=..` | אבחון התקשורת עם הדרייבר |
| `EN` / `DIS` | `OK` | החזקה / שחרור |
| `ZERO` | `OK` | המיקום הנוכחי = 0° |
| `ROT <deg> <rpm>` | `OK` בסוף התנועה | |
| `RUN <slot>` | `OK` בסוף התוכנית | |
| `STOP` | `OK` כשהבקר פנוי | באמצע תנועה: אין תשובה משלו — הפקודה הרצה עונה `ERR STOPPED` |
| `PLIST` | `OK 1=Streak A,3=Quadrants` | |
| `PGET <slot>` | `OK <program>` | |
| `PSET <slot> <program>` | `OK` | |
| `PDEL <slot>` | `OK` | |

### פורמט תוכנית

```
<name>|<step>|<step>|...

ROT <deg> <rpm>    rotate (negative = other direction)
WAIT <ms>          wait
HOLD               hold the dish (motor energised)
RELEASE            release the dish (motor free)
```

דוגמה:

```
PSET 1 Streak A|HOLD|ROT 90 20|WAIT 1500|ROT 90 20|WAIT 1500|ROT -180 10|RELEASE
```

### שדות STATUS

| שדה | משמעות |
|---|---|
| `EN` | 1 = המנוע מחזיק, 0 = משוחרר |
| `BUSY` | 1 = תנועה או תוכנית רצה |
| `STEP` | הצעד הנוכחי בתוכנית / מספר הצעדים |
| `POS` | זווית במעלות מאז הדלקה או `ZERO` |
| `DRV` | `0x21` = הדרייבר עונה; `0x00` = לא עונה (בדרך כלל אין 24V) |
| `CUR` | זרם המנוע שנקבע בתוכנה, mA (≈560) |
| `UP` | שניות מאז הדלקת הבקר. **ירידה = הבקר אותחל** |
| `URX` | כמה פעמים ערוץ התקשורת לדרייבר נתקע והופעל מחדש אוטומטית. צריך להישאר 0 |

### קודי שגיאה

| קוד | משמעות |
|---|---|
| `DRIVER` | הדרייבר לא עונה — המנוע לא הוזז |
| `BUSY` | תנועה אחרת רצה |
| `STOPPED` | נעצר ב-STOP |
| `EMPTY_SLOT` | אין תוכנית בתא |
| `BAD_SLOT` | מספר תא לא בין 1 ל-20 |
| `BAD_ARGS`, `BAD_STEP` | צעד לא תקין |
| `BAD_NAME` | שם ריק, ארוך מ-24 בייטים, או עם `, =` |
| `NO_STEPS`, `TOO_MANY_STEPS` | 0 צעדים / יותר מ-32 |
| `DEG_RANGE`, `RPM_RANGE`, `WAIT_RANGE` | ערך מחוץ לטווח |
| `UNKNOWN_CMD` | פקודה לא מוכרת |
| `LINE_TOO_LONG` | שורה ארוכה מ-1024 תווים |
| `FLASH` | כתיבה לזיכרון נכשלה |

## פתרון תקלות

| תסמין | סיבה אפשרית | מה עושים |
|---|---|---|
| `DRV=0x00`, ‏`NO DRIVER` | אין 24V על הדרייבר | למדוד 24V בין `VM` ל-`GND` של הדרייבר |
| `DIAG` מחזיר `A0=0` בכל הכתובות | אין 24V, או ערוץ התקשורת תקוע | לבדוק 24V; אם קיים — כפתור `RST` ב-XIAO |
| `DIAG` מחזיר `A0=4` בכל הכתובות | החוטים תקינים אבל הדרייבר לא עונה | לבדוק `MS1`/`MS2` ל-GND; לנסות את פין `PDN` במקום `USART` |
| `URX` עולה מעל 0 | ערוץ התקשורת נתקע והבקר תיקן אותו | המנוע ממשיך לעבוד; לרשום מתי זה קרה |
| הפורט תפוס (`Access is denied`) | ה-GUI, ה-Serial Monitor או platter.exe אחר מחזיק אותו | לסגור אותם |
| המחשב לא מזהה את הבקר על המטריצה | חוט ליד שקע ה-USB-C חוסם את התקע | להרחיק חוטים מהשקע |
| המנוע רועד ולא מסתובב | זוגות הסלילים מעורבבים | 24V כבוי, למדוד A1–A2 ≈ 9.3Ω ו-B1–B2 ≈ 9.3Ω |
| הצלחת מסתובבת לכיוון ההפוך | — | `INVERT_DIR = true` בקושחה, בלי לגעת בחוטים |
| לחיצה כפולה על `platter_gui.py` לא פותחת כלום | רץ עם Python של המערכת, בלי PySide6 | להשתמש ב-`PetriPlatter.bat` |
| הצריבה נכשלת | הבקר לא נכנס למצב צריבה | להחזיק BOOT בזמן חיבור ה-USB |

## התקנה אצל הלקוח

במחשב של הלקוח **לא צריך Python**, ולא צריך דרייבר ל-USB (Windows 10/11 מזהה את ה-XIAO לבד).

1. להעתיק את התיקייה `PetriPlatter` כולה, למשל ל-`C:\PetriPlatter`.
   - בתיקייה שיש בה הרשאת כתיבה (לא `C:\Program Files`) — התוכנה כותבת לידה את `platter.ini` ואת היומנים.
2. לחבר את הבקר ב-USB. לחבר 24V.
3. להפעיל את `platter_gui.exe`, לבחור את הפורט ו-**Connect**.
   הפורט נשמר ב-`platter.ini` — מעכשיו גם `platter.exe` משתמש בו.
4. **לבדוק כיוון:** בעמוד Manual control, סיבוב `0.25` (חיובי). הצלחת צריכה להסתובב
   **עם כיוון השעון כשמסתכלים עליה מלמעלה**. אם לא — לתקן `INVERT_DIR` בקושחה ולצרוב מחדש
   (לעשות את זה אצלנו, לפני המסירה).
5. להגדיר את התוכניות שהלקוח צריך, ולשמור.
6. **לסגור את ה-GUI** — הרובוט לא יכול לפתוח את הפורט כל עוד ה-GUI מחובר.
7. להגדיר ברובוט את הקריאות, עם הנתיב המלא. למשל:

```bash
C:\PetriPlatter\platter.exe run 1
```

   ולבדוק את קוד היציאה (`0` = הצליח).
